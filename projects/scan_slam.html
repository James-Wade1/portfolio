Scan-SLAM: Correlative Scan Matching and Pose-Graph Optimization in ROS 2

Graduate-level Autonomous Mobile Robots | Brigham Young University | 2026

Scan-SLAM is an educational ROS 2 (Jazzy) implementation of a complete 2D SLAM pipeline. The system combines a frontend based on correlative scan matching with a backend based on iterative pose-graph optimization, giving a hands-on implementation of the two core components found in modern lidar SLAM systems.

The project includes a custom 2D robot simulator for closed-loop testing, visualization tools for trajectory analysis and occupancy grid generation, and Docker support for reproducible builds. All components communicate through custom ROS 2 message types, reflecting a real-world system architecture.

System Architecture

The pipeline is split into four packages: the core SLAM node (scan_slam), custom message definitions (scan_slam_msgs), a Python simulator (scan_slam_sim), and visualization tools (scan_slam_viz).

Frontend — Correlative Scan Matching

The frontend subscribes to /scan (laser range data) and /odom (wheel odometry) topics. When the robot has traveled far enough from the last keyframe — measured by translation and rotation thresholds — a new keyframe is created and matched against the previous one.

Scan matching uses a lookup-table-based correlation search over (x, y, θ) space, as described by Olson [1]. An occupancy likelihood table is precomputed from the reference scan, and the new scan is swept through candidate poses to find the maximum-likelihood relative transform. The match is returned with a covariance matrix used downstream by the optimizer.

Loop closure detection compares each new keyframe against all prior keyframes. When a candidate pair falls within a proximity threshold, a scan match is attempted. High-confidence matches are added as loop-closure constraints to the pose graph, allowing the system to correct accumulated drift when revisiting known areas.

Backend — Pose-Graph Optimization

The backend maintains a pose graph where nodes represent keyframe poses and edges represent relative transform constraints between them (both sequential odometric constraints and loop-closure constraints). On each update, the optimizer linearizes the nonlinear least-squares problem — using either dense or sparse methods — and iterates until convergence. Corrected keyframe poses are then propagated back to the frontend so the occupancy map reflects the optimized trajectory.

The optimization formulation follows the tutorial by Grisetti et al. [2], providing a direct connection between the implementation and the mathematical foundations taught in the course.

Simulator and Visualization

A Python simulator (scan_slam_sim) provides a closed-loop test environment: it publishes synthetic laser scans and odometry with configurable drift, enabling full system testing without physical hardware. The visualization package (scan_slam_viz) generates trajectory comparisons, pose-graph structure plots, occupancy grids, and uncertainty ellipse analysis, all used in the results below.
